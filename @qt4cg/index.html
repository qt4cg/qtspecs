Casting to a record type: use the target’s `%fixed` values

In the following example…

declare record R(x as xs:integer, %fixed f := 1);
declare record S extends R(%fixed f := 2);
S(1) cast as R

…the result is { "x": 1, "f": 2 }, labeled as R. The value of f is kept because S(1) is already an instance of R, and the %fixed check is skipped in that case.

As a result, the cast returns an R record whose fixed field differs from R’s declaration. A cast to R should give R’s fixed values.

Proposal: If a field is declared %fixed in the target record type, the cast always uses the target type’s initializer instead of the input value. An error is still raised if the input is not an instance of the target type and has a different value for the fixed field.

Guarded expressions: FLWOR

The current spec says in 2.6.5 Guarded Expressions:

In a FLWOR expression, an expression that is logically dependent on the tuples in the tuple stream is guarded by the existence of a relevant tuple. This applies even where the expression does not actually reference any of the variable bindings in the tuple stream.

This might inhibit implementations from performing optimizations that could speed up valid code. For example, two popular XQuery 4.0 processors returns FORG0006 for…

declare function f($n, $e) {
  for $_ in 1 to $n where $e return 0
};
f(0, (1, 2))

BaseX in particular violates the guarded expression rule by rewriting this code to:

declare function f($n, $e) {
  if($e) { (1 to $n) ! 0 }
};
f(0, (1 to 2))

I wonder how strict we want to be?
