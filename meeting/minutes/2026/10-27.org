** PR #2981: 2980 Adaptive serialization: modes
:PROPERTIES:
:CUSTOM_ID: pr-2981
:ID:       E5E487F4-1EA0-47DE-A14E-3E4A36B487BE
:END:
+ See [[https://qt4cg.org/dashboard/#pr-2981][#2981]]

+ CG: continuation of previous changes. Can be used for debugging your code, or
  is a properly adaptive mode, which changes by type. In this PR attempt to
  separate the two modes. Added an adaptive-mode parameter:
  typed|readable|binary binary for output of xs:base64binary as true binary
  rather than text

+ JLO: previously adaptive was mostly implementation defined?
+ CG: certain parts eg doubles were spec defined. But it now becomes more implementation-dependent
+ JWL: binary equivalent to write-binary()?
+ CG: in effect yes

+ MK: I'm not enthusiastic, but I understand the motivation. I would prefer to
  avoid adding complexity. It seems a bit XQuery-oriented. I worry about how
  XSLT users will see it. Another hesitation: I haven't groked what binary
  output will look like and what it will achieve.

+ CG: binary output, in our use cases, we use serialization not only for strings
  but all sorts of data types. Extension to binary output would be natural for
  various APIs.
+ MK: you think of binary output as designed for other software to consume?
+ CG: yes. Our web server does http responses in binary, and here the data,
  serialized, can be rendered in binary.
+ MK: isn't that setting up binary as a competitor to XML or Json as an xchange
  format?
+ CG: it's only representing the individual data. Binary mode does the same as
  readable, so it could have been a separate parameter.

+ JLO: MK raised a good point - the binary mode is unclear. It isn't really
  adaptive - it is a proper mode for binary data throughout.
